# Sprint Wrap-Up Process

Use this process at the end of each development sprint before selecting the next sprint's implementation work.

1. Archive all completed planning documents.
2. Discuss current priorities post-sprint, and select likely upcoming work based on those priorities.
3. Discuss required design decisions and record a loose, high-level plan for the next sprint to pick up.
4. Add other low-priority ideas to the `Conceptualized, not yet planned` section of the roadmap for deferred content.
5. Perform a sprint retrospective/process improvements session.

Wrap-up outputs should usually include:

- updated the relevant active rolling board in `docs/Plans/`;
- archived completed planning documents under `docs/Archived/`;
- a short active next-sprint plan when there is enough agreement to preserve context;
- process-improvement notes when the sprint revealed workflow friction.
